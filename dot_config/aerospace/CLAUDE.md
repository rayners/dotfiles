# AeroSpace config

Tiling window manager config for macOS. Deployed to `~/.config/aerospace/aerospace.toml`.

## Edit the chezmoi source, not the deployed file

Source of truth is `~/.local/share/chezmoi/dot_config/aerospace/aerospace.toml.tmpl`.
Edits made directly to `~/.config/aerospace/aerospace.toml` are reverted by the next
`chezmoi apply`.

```bash
chezmoi diff ~/.config/aerospace/aerospace.toml   # check for drift
chezmoi apply ~/.config/aerospace                 # deploy (directory, so CLAUDE.md lands too)
aerospace reload-config                           # validate; parse errors surface here
```

`chezmoi execute-template < aerospace.toml.tmpl` renders the template without deploying.

## Floating app IDs live in machine-local chezmoi data

The `on-window-detected` floating rules are generated by a `range` loop over
`window_managers.common_floating_apps` and `window_managers.private_floating_apps`,
defined under `[data.window_managers]` in `~/.config/chezmoi/chezmoi.toml`. That file is
machine-local, which keeps work-specific apps out of the public dotfiles repo. Add apps
there rather than inlining bundle IDs in the template.

Bundle IDs: `aerospace list-apps` for running apps, or
`mdls -name kMDItemCFBundleIdentifier -r /Applications/App.app`.

## persistent-workspaces is maintained by hand

Under `config-version = 2` the fallback is an empty array — it is no longer inferred from
the keybindings. A workspace bound in `[mode.main.binding]` but missing from
`persistent-workspaces` disappears whenever it is empty. Add to both.

## Workspaces follow the main monitor

Every workspace is assigned to the "main" monitor by default, so the config needs no
monitor-specific logic: on the built-in display alone the pinned workspaces live there,
and when docked with the lid closed they follow whichever external is main.

`workspace-to-monitor-force-assignment` matches on the monitor's product name, which is
only discoverable via `aerospace list-monitors` while docked. An unmatched pattern has no
documented fallback, so any assignment added should end its pattern array with `'main'`.

## Pinned workspaces

C = Claude, E = Emacs, G = Ghostty, S = Slack, each fullscreened on detect. AeroSpace
drops fullscreen when a second tiling window enters the same workspace (Slack huddles and
preference panes are the likely trigger). If that becomes a problem, add
`layout --workspace S accordion` to `after-startup-command`.

## Testing callback changes

`aerospace run-callback --for-every-window on-window-detected` re-applies the rules to
already-open windows, so callbacks can be tested without relaunching apps. It forwards
each command's stdout and stderr.
